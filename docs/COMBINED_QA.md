# Combined ESP32-C5 quality check

This integration branch is for hardware QA before submitting Net Scanner.
It combines upstream 1.0.16 with:

- Prepared Net Scanner: `9f73d3ff3b6e2143a61e7f1ba4d700323b1a7785`.
- Handshake cracker PR #49: `58bc6c08792308fa6453f347735bea35f04aac35`.
- Wardrive PR #50: `41509ed293d0751b090c800b99448810d4a9a7c2`.

Shared menu conflicts were resolved by retaining all entries. Device Inspector
and Wi-Fi Guard remain included. The handshake production feature code is unmodified. Wardrive additionally
carries the borrowed-interface DNS restoration fix documented below. The unpublished detector-dual-band feature
branch is not part of these two PRs and is not included.

Use the SDK and opt-in memory profile in NET_SCANNER_BUILD.md. No changes to
partitions, upstream defaults or dependency versions are required. This is a
combined test image; the upstream Net Scanner PR should stay feature-scoped.

## Local PowerShell build and flash

From an existing repository in an ESP-IDF PowerShell terminal:

```powershell
git fetch https://github.com/l3allzh4ck/the_poom.git integration/net-scanner-quality-check
git worktree add --detach ../poom-quality-check FETCH_HEAD
Set-Location ../poom-quality-check
git submodule update --init --recursive

$expectedIdf = "95b6f32350e1118181d1a1c375972cbcd85a6540"
if ((git -C "$env:IDF_PATH" rev-parse HEAD).Trim() -ne $expectedIdf) {
    throw "Export the Wardrive-verified ESP-IDF snapshot before continuing."
}

$buildDir = "build-quality-release"
python "$env:IDF_PATH/tools/idf.py" -B $buildDir -D IDF_TARGET=esp32c5 "-DSDKCONFIG=$buildDir/sdkconfig" "-DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.net_scanner_release" reconfigure build size
# Continue only if the build and partition-size checks succeed.
$port = "COM5" # Replace with your POOM port.
python "$env:IDF_PATH/tools/idf.py" -B $buildDir -p $port flash
python "$env:IDF_PATH/tools/idf.py" -B $buildDir -p $port monitor --no-reset
```

The new worktree preserves the current working branch and its local files.
Use a new build directory; do not reuse an older generated sdkconfig. There is
no erase-flash step. Standard flashing writes bootloader, partition table, OTA
metadata and the application; existing NVS and filesystem partitions are not
blanked. Confirm successful write verification and boot from this build.

## Wardrive transition investigation

Owner hardware QA confirmed repeated Net Scanner discovery/audit and SD report
saving. Wardrive subsequently appeared to collect no BLE reports and became
unresponsive while leaving the app. The supplied console log only contained
scanner traces; it does not establish the BLE failure stage or internal heap
headroom. Combined hardware acceptance remains blocked.

`sdkconfig.qa_diagnostics` enables the existing opt-in Wardrive diagnostics.
Additional stage traces bracket BLE initialization and teardown SDK calls,
report internal/DMA heap and largest internal block, show worker suspension
and release, and report UI stop/exit wait state. These are diagnostic changes,
not a claimed fix. They do not forcibly terminate radio tasks or change stock
radio ownership, TLS, partitions or the release memory profile.

Update this QA branch and use the pinned SDK with a fresh build/configuration:

```powershell
git pull --ff-only
$buildDir = "build-quality-diagnostics"
python "$env:IDF_PATH/tools/idf.py" -B $buildDir -D IDF_TARGET=esp32c5 "-DSDKCONFIG=$buildDir/sdkconfig" "-DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.net_scanner_release;sdkconfig.qa_diagnostics" build size
# After successful build/size checks, using your device's COM port:
python "$env:IDF_PATH/tools/idf.py" -B $buildDir -p COM5 flash
python "$env:IDF_PATH/tools/idf.py" -B $buildDir -p COM5 monitor --no-reset
```

After power-cycling and attaching the monitor without reset, first test
Wardrive BLE-only recording/stop/exit from a fresh boot. Then repeat the same
Wardrive test after a Net Scanner audit/report/exit. Keep a known BLE advertiser
nearby and capture the full `[wardrive ...]` output, selected mode, whether the
radio ever starts, and whether stopping recording or leaving the app triggers
the failure. Avoid automatic monitor resets: the owner reported a separate
monitor/reset interaction, with no-reset attachment working after reconnect.

### Reproduced combined-mode cleanup failure and fix

Owner logs confirmed a successful combined session before Net Scanner (23 Wi-Fi
and 20 BLE devices). After the scanner audit, combined mode stopped with
`radio_error=0x5001`, saved 10 Wi-Fi devices and no BLE devices, then repeatedly
retried Wi-Fi cleanup on exit. This run is not hardware acceptance.

The pinned SDK returns `ESP_ERR_ESP_NETIF_INVALID_PARAMS` (0x5001) when
`esp_netif_set_dns_info` is given an empty address. Wardrive snapshots DNS from
an existing station interface, including legitimately empty backup/fallback
slots. Restoring those empty slots retained the borrowed-interface ownership
flag indefinitely, preventing subsequent BLE windows and completion of exit.
The previous host mock accepted empty DNS entries and missed this failure.

The QA fix skips empty DNS slots: the pinned SDK's IP restoration already
clears main/backup DNS, while DHCP preserves fallback and Wardrive does not
change it. Populated entries are restored after restarting the previous DHCP
client, since that restart also clears main/backup DNS. Genuine restoration
errors still retain ownership for retry; no cleanup errors are masked and no
foreign interface is destroyed.

The updated SDK-faithful regression failed before the fix and passes afterward.
Coverage includes empty DNS, populated main with empty backup/fallback, repeated
borrowed-interface cycles, populated static DNS, and a genuine restore failure
followed by retry. Radio ownership/rollback tests, the Wardrive host suite and
the pinned ESP32-C5 diagnostic firmware build pass. Owner retest remains pending.

Keep the diagnostic build configuration for the retest. After updating this
branch, `idf.py -B build-quality-diagnostics build size` rebuilds the changed
adapter; then flash and attach the monitor with `--no-reset`. Repeat Net Scanner
audit/exit -> Wardrive Wi-Fi + BLE -> stop/exit. Confirm both device counts,
`saved=1`, `errors=0`, `radio_error=0x0` and return to the responsive main menu,
without repeated `deinit=0x5001` messages.


### Protected background navigation and exit choices

B from live/GPS/statistics pages now opens a background-recording notice;
either A or B acknowledges it without changing pause or radio state. A paused
session gets an accurate "will remain paused" message. The main menu labels
are "Resume Active Session" and "Resume Paused Session"; selecting the paused
entry explicitly resumes recording.

B from the main Wardrive menu with any active/paused session opens an exit
warning. "Save session and exit" is selected by default on every entry.
UP/DOWN changes the selection and A confirms. B cancels with state unchanged.
"Exit without saving" closes/discards only the current recorder's files after
radio completion; saved sessions are preserved. SD failures keep the user in
Wardrive with an error. Existing hold-B save/stop confirmation remains available.

Regression coverage includes both notice acknowledgement buttons, background
navigation from all three live pages, active-time continuity, paused/resumed
labels, exit-warning cancellation/default reset, radio-drain ordering, both exit
choices, SD failures, real current-session deletion and preservation of prior
sessions and unknown files. Verify the new flow on hardware, using a disposable
recording to test discard and checking the main menu remains responsive.
